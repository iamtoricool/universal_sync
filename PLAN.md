# `universal_sync` — implementation plan

> Status: **draft v3 for review**. No code written yet.
> Target SDK: Dart **3.14.0** (stable, 2026-11-11) · Drift **2.34.x** stable · Flutter 3.50.0
> Goal: a Drift-native, compile-time-typed, standalone offline-first sync core with no bundled transport adapters.

**Implementation status (MVP).** P0–P3.5 and P5 are implemented in this
repository: contracts, package-owned Drift schema, journal, engine, typed write
facade, fake transport, tests, docs, CI. P4 (the `build_runner` generator) and
P6 (reconcile/isolate extras) remain. The entity description is currently
hand-written in the shape the generator will emit (`SyncEntity(...)`); see
`README.md` and the status section at the end of this file.

**Revision history**

- **v2** — fixed the outbox state machine (sent rows immutable), removed the self-contradictory
  `revision`, added durable conflicts, bootstrap policies, bulk paths, capability negotiation and a
  serializable failure taxonomy.
- **v3** — offline-sequence audit (`create → update → delete`, multi-key ordering). Replaced
  attempt-count immutability with an explicit **delivery-certainty** flag, added **not-sent release**
  and **promotion** rules, changed `create → delete` to coalesce into an idempotent `delete`
  instead of cancelling, made the tombstone pull-guard survive acks, mandated engine timestamp
  stamping, added coalescing observability, and documented the cross-entity ordering boundary.

## 0. Why this design (validated findings)

Three assumptions were tested in a throwaway sandbox before designing anything:

1. **Drift silently drops external `Table` classes.**
   Adding a package-owned `Table` to a consumer's `@DriftDatabase(tables: [...])` produces
   `"PkgSyncOutbox is not understood by drift"` and the table is then **omitted from the generated
   database with no compile error**. A package therefore cannot ask consumers to add its tables to
   their `@DriftDatabase` and expect them to be generated.
   → We own the sync schema and bind its generated table infos to the consumer's database at
   runtime.

2. **A package-generated `TableInfo` can be bound to the consumer's `GeneratedDatabase`.**
   `$OutboxTable(userDb)` then supports typed `select` / `insert` / `update`, drift `watch()`,
   `insertReturning`, and a **single transaction spanning the user's tables and our outbox**.
   → We own our schema, generate it once inside our repo, commit the generated code, and bind it to
   the consumer's database at runtime.

3. **Drift companions give typed deltas for free.**
   `TasksCompanion(title: Value('x')).toColumns(true)` yields only the present columns with their
   SQL names (`updated_at`, not `updatedAt`).
   → A type-safe *patch* operation is possible without exposing raw maps at the API boundary.

A fourth finding came from the offline-sequence audit:

4. **"Attempted" is not "possibly delivered".** A claim increments `attempts` before the transport
   is called, so an airplane-mode failure would make a write immutable even though nothing left the
   device. Coupling immutability to attempt count silently turns a compact offline edit session into
   a multi-request replay. Immutability must be bound to *delivery certainty*, supplied by the
   adapter, not to an attempt counter. See §4.4 and §7.

Consequence: type safety holds across the **developer-facing API**, and the only untyped surface is
the canonical wire JSON between the engine and the adapter — which is exactly where a wire format
belongs.

## 1. Positioning

`universal_sync` is a **headless, Drift-native sync core**. It ships:

- the transport **contract + capability negotiation** (no adapters),
- the sync **engine** (drain, pull, conflicts, retries, events),
- its own **Drift schema** for outbox / cursors / tombstones / conflicts / dead letters,
- a **build_runner generator** that turns the developer's existing Drift tables into typed sync
  facades,
- test doubles, a test harness, and a **transport conformance suite** so adapter authors can
  validate their work.

It does **not** ship: Supabase/REST/Firebase adapters, auth, HTTP, encryption, realtime,
background scheduling, or UI.

| Layer | Owner |
|---|---|
| Domain tables/rows/companions (`Task`, `TasksCompanion`) | Developer's existing Drift schema |
| Typed sync facade (`sync.tasks.save(...)`) | **Generated by us** |
| Engine, outbox, cursors, conflicts, events | **Us** |
| Canonical wire JSON (`Map<String, Object?>`) | Us (format), adapters (transport) |
| Backend I/O (`SyncTransport`) | **Adapter packages**, e.g. `universal_sync_supabase` |
| Reads, joins, watch queries, existing transactions, DAOs | Untouched |

## 3. Architecture

```
 app code (typed)                          sync.tasks.save(TasksCompanion.insert(...))
      │
      ▼
 generated SyncEntityAdapter<Tbl, Row, Key>     typed encode/decode, key, updatedAt, owner
      │
      ▼
 engine  ── one drift transaction ──▶  user's tables  +  us_outbox / us_tombstones
      │
      ▼
 SyncTransport (contract + capabilities)        implemented by adapter packages
      │
      ▼
 remote backend
```

### Write path

```
create/save/patch/remove/markDirty
  1. typed validation: payload size, ownership (generated getters, never string keys)
  2. stamp server-declared columns the caller omitted (updatedAt, owner) from SyncClock/SyncSession
  3. db.transaction (composes with the caller's transaction via savepoints):
       typed drift write on the user's table
       coalesce/append outbox entry (see §7 rules)
  4. if autoDrain: debounce → single-flight drain
```

### Drain path

```
claim:  UPDATE us_outbox
          SET state='inflight', delivered_maybe=1, attempts=attempts+1,
              lease_until=?, leased_by=?
        WHERE sequence IN (<select query below>) RETURNING *

select: state='pending' AND next_attempt_at <= :now
        AND NOT EXISTS (older pending/inflight row for the same entity+key)   ← per-key ordering
        ORDER BY sequence LIMIT :n

group by entity → chunk by count + maxBatchBytes, ordered by sequence
transport.push(batch) → PushOutcome
   applied      → same txn: reconcile serverRow, delete row, supersede older obsolete rows
   rejected     → TransientFailure(notSent)      → release row as coalescible (see §7 rule 5)
                  TransientFailure(maybeApplied) → back to pending, backoff, no `failures` cost
                  RateLimited                    → back to pending, honor retryAfter, notSent
                  AuthFailure                    → release lease, emit AuthRequired, stop drain
                  RevisionConflict               → reconcile serverRow, retry as upsert
                  other permanent                → move to us_dead_letters, emit ChangeParked,
                                                   promote the next pending row for that key
contract violation (acks missing sequences) → release leases, emit ContractViolation, keep rows
maintenance: tombstone purge (cursor-gated), outbox pressure check
emit DrainCompleted
```

`drain()` loops until no row is claimable or a time/iteration budget is exhausted
(`maxDrainIterations`, `drainTimeBudget`), so a 10k backlog does not require 200 external calls.

### Pull path per entity

```
cursor = us_cursors[entity] (opaque or keyset)
loop:
  transport.pull(cursor, limit) → PullPage
  transaction:
    batch-select pending keys for the page (one query)
    for each row:  if a tombstone exists for key → skip (local intent wins; persists after ack)
                   skip unchanged (remote.updatedAt <= local.updatedAt and no pending change)
                   if a pending outbox entry exists → conflict policy or us_conflicts row
                   else → batched typed upsert
    for each deleted key: record remote tombstone first (even if absent locally), then batched delete
    persist nextCursor in the same transaction
  until !hasMore
emit RowsPulled per page
```

Crash safety: cursor and page data commit together; re-applying a page is idempotent. Outbox rows are
leased, so a killed process resumes after `lease_until`, and `open()` reclaims expired leases
immediately.

## 4. Public contracts

### 4.1 Transport + capabilities

```dart
abstract base class SyncTransport {
  /// Capabilities are validated against registered entities at `open()`.
  SyncTransportCapabilities get capabilities;

  Future<PushOutcome> push(PushBatch batch);
  Future<PullPage> pull(PullPageRequest request);

  /// Optional: backends that can apply multiple tables/entities atomically.
  Future<Map<SyncEntityRef, PushOutcome>> pushMany(List<PushBatch> batches) async { /* loop */ }

  /// Optional: release HTTP clients, sockets, subscriptions. Never closes the database.
  Future<void> close() async {}
}

final class SyncTransportCapabilities {
  final bool serverTimestamps;      // required when an entity has server-managed columns
  final bool tombstones;            // required when an entity declares a tombstone source
  final bool idempotency;           // server dedupes (entity, idempotencyKey)
  final bool atomicMultiEntity;     // enables pushMany batching
  final bool deliveryCertainty;     // adapter can distinguish notSent from maybeApplied
  final Set<CursorKind> cursors;    // {opaque, keyset}
}
```

`SyncTransport` is an `abstract base class` (not `abstract interface class`) so adapters **extend**
and inherit `pushMany`/`close` defaults. `open()` cross-checks capabilities × entities and throws a
typed, actionable `SyncCapabilityMismatch`. When `deliveryCertainty` is `false`, all transient
failures are treated as `maybeApplied` (safe, but offline edit sessions replay as in v2).

### 4.2 Entity descriptor (generated, consumed by adapters)

```dart
final class SyncEntityRef {
  final String table;                          // SQL table name
  final List<String> primaryKey;               // ordered column names (composite-ready)
  final String? updatedAtColumn;
  final String? ownerColumn;
  final String? deletedAtColumn;
  final Map<String, SyncColumnKind> columns;   // wire kind per column
  final Set<String> serverManagedColumns;      // omitted from push payloads
}

enum SyncColumnKind { text, integer, real, boolean, dateTime, blob, enumName, enumIndex, json }
```

Adapters never type table names or column names by hand; they read them from `SyncEntityRef`.

### 4.3 Push DTOs

```dart
final class PushBatch {
  final SyncEntityRef entity;               // one entity per call → trivial adapter impls
  final List<SyncChange> changes;           // ordered by local sequence
  final int attempt;                        // attempts of the first change, for observability
}

/// `insert` is deliberately absent: every create is an upsert so retries are idempotent.
enum SyncChangeKind { upsert, update, delete }

final class SyncChange {
  final int sequence;                       // ack correlation; unique per install
  final SyncChangeKind kind;
  final Map<String, Object?> row;           // full after-image (column names); absent for delete
  final Map<String, Object?>? delta;        // update: changed columns only
  final String idempotencyKey;              // '<installId>:<sequence>' — stable across retries
}

final class PushOutcome {
  final List<ChangeAck> acks;               // MUST cover every sequence
}

enum ChangeStatus { applied, rejected, superseded }

final class ChangeAck {
  final int sequence;
  final ChangeStatus status;
  final Map<String, Object?>? serverRow;    // authoritative row (timestamps, defaults)
  final SyncFailure? failure;
}
```

**Contract rules**

1. `acks` must cover every `sequence`; otherwise the batch is failed with
   `TransportContractViolation`, rows are kept, and a programming error is reported.
2. `superseded` means the server already holds a higher revision for this record; the engine drops
   the row without treating it as an error.
3. `applied` acks for entities with `serverManagedColumns` must carry `serverRow`; otherwise the ack
   is rejected as a contract violation (never silently synthesize a row).
4. A `delete` for a row that does not exist is **idempotent**: the adapter maps "not found" to
   `applied`, never to a failure. This is what makes the `create → delete` coalescing rule safe.

### 4.4 Failure taxonomy + delivery certainty + serialization

```dart
enum DeliveryCertainty { notSent, maybeApplied }

sealed class SyncFailure implements Exception {
  SyncFailureCode get code;      // stable, persisted
  String get message;            // human readable, never contains row data
  bool get retryable;
  Duration? get retryAfter;
  DeliveryCertainty get certainty; // default: maybeApplied (conservative)

  Map<String, Object?> toJson();                  // required — dead letters must round-trip
  static SyncFailure fromJson(Map<String, Object?> json); // unknown code → UnknownFailure
}

enum SyncFailureCode {
  auth, forbidden, rateLimited, transient, revisionConflict, permanent, unknown,
}

final class AuthFailure       extends SyncFailure  // user action required; stops drain
final class ForbiddenFailure  extends SyncFailure  // RLS / policy; permanent for this change
final class RateLimited       extends SyncFailure  // honors retryAfter; certainty = notSent
final class TransientFailure  extends SyncFailure  // certainty is adapter-supplied
final class RevisionConflict  extends SyncFailure  // carries serverRow → engine reconciles
final class PermanentFailure  extends SyncFailure  // validation → dead letter
final class UnknownFailure    extends SyncFailure  // forward-compatible fallback
```

**`notSent` is a promise, not a guess.** Adapters may report it only when they can prove the request
never reached the server (connection refused, DNS failure, airplane mode, request rejected before
write). Timeouts, resets after write, and 5xx responses are `maybeApplied`. A misreported `notSent`
can drop an update, so the contract tests include a negative case for it.

No string matching, no `isTransientError` callback, no `sensitiveFields` log scrubbing. Dead letters
written by older package versions remain loadable.

### 4.5 Pull DTOs

```dart
sealed class SyncCursor { const SyncCursor(); }
final class OpaqueCursor extends SyncCursor { final String token; }        // preferred
final class KeysetCursor extends SyncCursor {                              // for dumb REST
  final DateTime updatedAt;
  final List<Object?> key;                                                 // tiebreaker
}

enum CursorKind { opaque, keyset }

final class PullPageRequest {
  final SyncEntityRef entity;
  final SyncCursor? cursor;
  final int limit;
}

final class PullPage {
  final List<Map<String, Object?>> rows;       // FULL after-images, all non-generated columns
  final List<List<Object?>> deletedKeys;       // composite-safe PK value lists
  final SyncCursor? nextCursor;
  final bool hasMore;                          // engine loops until false → no truncation
}
```

Contract rule: `rows` are **full rows**. Partial rows are rejected with a typed
`SyncCapabilityMismatch`/`ProtocolViolation` at the page boundary, because partial application would
silently null out local columns.

### 4.6 Session and clock

```dart
abstract interface class SyncSession {
  String? get userId;
  Stream<String?> get userIdChanges;
}

abstract interface class SyncClock {
  DateTime now();
}
```

Both injectable. A `userId` change triggers `purgeOnUserChange` (default `true`), see §5.7.

## 5. Typed developer API

### 5.1 Annotations

```dart
@Syncable(key: #id, updatedAt: #updatedAt, owner: #userId)
class Tasks extends Table { /* unchanged */ }

@SyncDatabase(prefix: 'Us')
@DriftDatabase(tables: [Tasks, Projects])
class AppDatabase extends _$AppDatabase { /* unchanged */ }
```

- `key` — names the Dart getter(s) of the primary key. v1 codegen supports exactly one; omit it and
  the generator infers the single declared primary-key column, failing with an actionable
  diagnostic otherwise. Storage and wire format are composite-ready from day one.
- `updatedAt` — required for `newestWins` and unchanged-row skipping. The engine **stamps** it on
  every synced write when the caller omitted it (§5.3).
- `owner` — optional; enables local ownership checks, per-user purge, and `ownerAutoFill`.
- `prefix` — optional generated-name prefix to avoid collisions with existing app classes.
- No changes to the developer's `schemaVersion`, migrations, or existing generated code.

### 5.2 Usage

```dart
final sync = await UniversalSync.open(
  database: db,
  registry: appSyncRegistry(db),       // generated
  transport: MyRestTransport(),        // from an adapter package
  session: mySession,
  bootstrap: const SyncBootstrap.mergeByUpdatedAt(),
  options: const SyncOptions(),
);

await sync.tasks.create(TasksCompanion.insert(
  id: 't1', title: 'Ship it', updatedAt: clock.now(),
));

await sync.tasks.patch(TasksCompanion(title: const Value('Ship it today')));
await sync.tasks.remove('t1');

await db.transaction(() async {        // composes inside an existing transaction
  await sync.tasks.create(...);
  await sync.projects.create(...);
});                                    // local rows + outbox entries atomic together

await sync.syncNow();                  // push then pull (default SyncOrder.pushThenPull)
```

Bulk paths:

```dart
await sync.tasks.saveAll(companions);  // drift batch(), one transaction, one coalescing pass

await sync.unitOfWork((u) {            // one transaction, one coalescing pass, all entities
  u.tasks.create(...);
  u.projects.save(...);
});
```

### 5.3 Generated per-entity facade — frozen signatures

| Member | Exact signature | Semantics |
|---|---|---|
| `create` | `Future<Row> create(Insertable<Row> c)` | `INSERT` + outbox `upsert` |
| `save` | `Future<Row> save(Insertable<Row> c)` | `insertOnConflictUpdate` + outbox `upsert` |
| `patch` | `Future<Row?> patch(Insertable<Row> c)` | typed delta from `Value.present`; `null` if no row |
| `remove` | `Future<bool> remove(Key key)` | `DELETE` + tombstone + outbox `delete` |
| `removeMany` | `Future<int> removeMany(Iterable<Key> keys)` | batched deletes |
| `saveAll` | `Future<int> saveAll(Iterable<Insertable<Row>> cs)` | batched writes |
| `markDirty` | `Future<void> markDirty(Key key, {required SyncChangeKind kind})` | outbox only |
| `find` | `Future<Row?> find(Key key)` | typed read |
| `watch` | `Stream<List<Row>> watch()` | typed drift stream |
| `query` | `SimpleSelectStatement<Tbl, Row> query()` | raw drift escape hatch |

**Column stamping (new in v3).** When the entity declares `updatedAt` and the companion does not
provide it, the adapter injects `Value(clock.now().toUtc())` via `companion.copyWith(...)` on
`create`, `save` and `patch`. Same for `owner` when `ownerAutoFill` is on. Without this, a
`patch(title: Value('B'))` keeps a stale `updated_at`, so offline edits lose `newestWins` against a
stale server row. Callers can always override by providing the value explicitly.

**`markDirty`** replaces v1's misleading `publish` (it is **not** atomic with a DAO write; documented
as advanced use). In debug builds it asserts that the local row exists for `upsert`/`update` and does
not exist for `delete`.

These signatures are frozen in P1 and guarded by a generated-output golden test; codegen must never
drift them silently.

### 5.4 Root engine surface

```dart
final class UniversalSync<DB extends GeneratedDatabase> {
  Future<SyncReport> drain();
  Future<SyncReport> pull();
  Future<SyncReport> syncNow({bool push = true, bool pull = true, SyncCancelToken? cancel});
  Future<SyncReport> bootstrap();              // idempotent, resumable
  Stream<SyncEvent> get events;
  SyncStatus get status;
  Stream<SyncStatus> get statusStream;         // idle | draining | pulling | offline
                                               // | authRequired | schemaError
  Future<SyncDiagnostics> diagnostics();
  Future<List<ConflictRecord>> conflicts();
  Future<void> resolveConflict(int id, ConflictResolution resolution);
  Stream<ConflictRecord> watchConflicts();
  Future<int> retryParked();
  Future<void> discardParked();                // explicit, never automatic
  Future<void> purge({bool localData = false});
  Future<void> dispose();                      // returns inflight → pending, cancels timers
}

final class SyncReport {
  final int pushed;        // changes acknowledged as applied
  final int failed;        // rejected, retryable
  final int parked;        // rejected, permanent
  final int pulled;        // rows applied
  final int conflicts;     // conflicts detected
  final int coalesced;     // operations merged into another outbox row
  final int cancelled;     // operations that cancelled out (opt-in create+delete)
  final Duration elapsed;
}
```

`coalesced`/`cancelled` close the "did anything happen?" ambiguity: five offline writes that collapse
into one push must be visible in the report (`pushed = 1, coalesced = 3, cancelled = 1`), otherwise
developers cannot distinguish "synced quietly" from "nothing ran".

`dispose()` never closes the consumer's database; it cancels timers, aborts in-flight work and
releases leases.

### 5.5 Options

```dart
final class SyncOptions {
  final int pushBatchSize;                 // 50 rows
  final int pullPageSize;                  // 500 rows
  final int maxPayloadBytes;               // 1 MiB per change (100 MiB hard cap)
  final int maxBatchBytes;                 // 4 MiB per push request
  final Backoff backoff;                   // exponential, jittered, capped
  final int maxAttempts;                   // budget for non-transient failures only
  final int maxDrainIterations;            // 1000
  final Duration drainTimeBudget;          // 30 s per drain() call
  final Duration lease;                    // 2 min
  final Duration tombstoneRetention;       // 30 d
  final int maxOutboxBytes;                // 32 MiB → OutboxPressure event
  final bool autoDrain;                    // false by default
  final Duration autoDrainDebounce;        // 500 ms
  final int pushConcurrency;               // 1
  final int pullConcurrency;               // 1
  final bool skipUnchangedPulls;           // true
  final bool purgeOnUserChange;            // true
  final bool stampUpdatedAt;               // true — engine sets updatedAt when omitted
  final bool cancelUnsyncedCreateThenDelete; // false — see §7 coalescing rules
  final bool promoteDependentUpdates;      // true — see §7 promotion rules
  final bool emitPayloads;                 // false → events carry no row data
  final bool validateSchema;               // true
  final SyncClock clock;
}

sealed class Backoff { const Backoff(); }
final class ExponentialBackoff extends Backoff { /* initial, factor, max, jitter */ }
final class FixedBackoff       extends Backoff { /* delay */ }
final class NoBackoff          extends Backoff {}
```

Every option is read by the engine (no dead knobs). `attempts` (all sends, observability),
`failures` (budget for `maxAttempts`) and `delivered_maybe` (immutability) are three separate
concepts, so `TransientFailure(notSent)` never consumes the permanent-failure budget and never
freezes a row.

### 5.6 Events

```dart
sealed class SyncEvent { DateTime get at; }

final class DrainStarted        extends SyncEvent
final class DrainCompleted      extends SyncEvent
final class ChangePushed        extends SyncEvent  // entity + key + kind
final class ChangeCoalesced     extends SyncEvent  // entity + key + merged kinds
final class ChangeCancelled     extends SyncEvent  // entity + key (opt-in create+delete)
final class ChangeParked        extends SyncEvent  // dead letter + SyncFailure
final class ChangePromoted      extends SyncEvent  // update → upsert after a predecessor failure
final class RetryScheduled      extends SyncEvent  // entity + key + nextAttemptAt + failure
final class RowsPulled          extends SyncEvent  // entity + count + hadMore
final class ConflictDetected    extends SyncEvent  // entity + key + policy
final class ConflictResolved    extends SyncEvent  // entity + key + winner
final class AuthRequired        extends SyncEvent
final class OfflineDetected     extends SyncEvent
final class OutboxPressure      extends SyncEvent  // over maxOutboxBytes
final class TransportContractViolation extends SyncEvent
final class SyncSchemaMismatch  extends SyncEvent
```

Events carry entity refs, keys and classifications — never row payloads unless `emitPayloads: true`.
PII safety is structural, not a masking pass.

### 5.7 Session, ownership and purge

- `ownerAutoFill: true` (default when `owner` is declared): `create`/`save` inject
  `session.userId` when absent and reject a mismatched value with a typed `OwnershipViolation`.
- Pull rows whose owner differs from `session.userId` are skipped and reported, never written.
- `purgeOnUserChange: true`: on `userId` change, cancel in-flight work, clear outbox, cursors,
  tombstones, conflicts and dead letters, optionally local data, and reset `bootstrap_done`.
- `logout()` is an explicit alias for `purge(localData: true)`.

### 5.8 Bootstrap for existing projects

```dart
sealed class SyncBootstrap { const SyncBootstrap(); }
final class UploadLocal      extends SyncBootstrap  // mark existing rows as pending upserts
final class ServerWins       extends SyncBootstrap  // full pull; local rows not newer are replaced
final class MergeByUpdatedAt extends SyncBootstrap  // recommended adoption default
final class SkipBootstrap    extends SyncBootstrap  // explicit: current-cursor semantics
```

- Runs exactly once, recorded by `us_meta.bootstrap_done` in the same transaction as cursor init.
- `bootstrap()` is idempotent and resumable (chunked, safe to interrupt and rerun).
- `UploadLocal` and `MergeByUpdatedAt` reuse the bulk write path (§5.2).
- Without this, dropping the package into an app with existing rows silently overwrites or silently
  never uploads them — the exact trust failure this project exists to avoid.

## 6. Wire protocol (canonical, `doc/protocol.md`)

- Keys are **SQL column names** (`updated_at`), not Dart getter names (`updatedAt`).
- `DateTime` → ISO-8601 UTC string; `Uint8List` → base64; enums → name (`enumName`) or index
  (`enumIndex`); `Value.absent` omitted; `null` preserved as JSON `null`.
- `idempotencyKey = '<install_id>:<sequence>'`. `install_id` is generated once per database and
  stored in `us_meta`; sequences are only unique per install.
- No `revision` field. Acknowledgment correlates on `sequence`; identity is guaranteed by the
  delivery-certainty rule (§7), not by a version number the adapter could get wrong.
- **Server-authoritative timestamps**: `ChangeAck.serverRow` is reconciled into the local row for
  every entity with `serverManagedColumns`.
- Pull cursors are opaque or keyset; the engine loops on `hasMore` and never derives a cursor from
  the device clock.
- Deletes travel as tombstones in both directions. `DELETE` is idempotent; "not found" is `applied`.
- Push payloads omit `serverManagedColumns`; pull pages must contain full rows.
- **Ordering:** per-key ordering is guaranteed (one outstanding change per key, ascending sequence).
  Cross-key and cross-entity ordering is **not** guaranteed; see §9.
- Backend requirements checklist (documented for adapter authors): stable per-row revision column,
  tombstones for deletes, `return=representation`-style echoes, monotonic cursor, idempotent
  upsert/update/delete, delivery certainty, `maxBatchBytes` respected.

## 7. Local schema (owned by `universal_sync`)

```sql
CREATE TABLE us_meta (
  key   TEXT NOT NULL PRIMARY KEY,
  value TEXT NOT NULL                -- schema_version, install_id, bootstrap_done, last_maintenance_at
);

CREATE TABLE us_outbox (
  sequence          INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
  entity            TEXT    NOT NULL,
  key_hash          BLOB    NOT NULL,  -- 16-byte digest of the canonical key encoding
  key_json          TEXT    NOT NULL,  -- canonical JSON array of PK values (wire + debug)
  kind              TEXT    NOT NULL,  -- upsert | update | delete
  row_json          TEXT,              -- full after-image (upsert)
  delta_json        TEXT,              -- changed columns (update)
  state             TEXT    NOT NULL,  -- pending | inflight
  delivered_maybe   INTEGER NOT NULL DEFAULT 0, -- 1 = may have reached the server (immutable)
  attempts          INTEGER NOT NULL DEFAULT 0, -- every claim (observability)
  failures          INTEGER NOT NULL DEFAULT 0, -- non-transient failures (budget)
  next_attempt_at   INTEGER NOT NULL,
  lease_until       INTEGER,
  leased_by         TEXT,               -- instance id of the drainer
  last_failure_json TEXT,               -- serialized SyncFailure (incl. certainty)
  created_at        INTEGER NOT NULL,
  updated_at        INTEGER NOT NULL
);

-- Coalescing target: at most one never-proven-undelivered pending row per key.
CREATE UNIQUE INDEX us_outbox_coalesce_uq
  ON us_outbox(entity, key_hash) WHERE state = 'pending' AND delivered_maybe = 0;
CREATE INDEX us_outbox_ready  ON us_outbox(state, next_attempt_at, sequence);
CREATE INDEX us_outbox_key    ON us_outbox(entity, key_hash, sequence);

CREATE TABLE us_cursors (
  entity      TEXT NOT NULL PRIMARY KEY,
  cursor_json TEXT,
  updated_at  INTEGER NOT NULL
);

CREATE TABLE us_tombstones (
  entity     TEXT NOT NULL,
  key_hash   BLOB NOT NULL,
  key_json   TEXT NOT NULL,
  source     TEXT NOT NULL,          -- local | remote
  deleted_at INTEGER NOT NULL,
  acked_at   INTEGER,                -- local deletes: set when the push is acked
  PRIMARY KEY (entity, key_hash)
);
CREATE INDEX us_tombstones_purge ON us_tombstones(acked_at, deleted_at);

CREATE TABLE us_conflicts (
  id           INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
  entity       TEXT NOT NULL,
  key_hash     BLOB NOT NULL,
  key_json     TEXT NOT NULL,
  local_json   TEXT,
  remote_json  TEXT NOT NULL,
  local_status TEXT NOT NULL,        -- pending | inflight | parked | absent
  detected_at  INTEGER NOT NULL,
  resolved_at  INTEGER
);
CREATE UNIQUE INDEX us_conflicts_open_uq
  ON us_conflicts(entity, key_hash) WHERE resolved_at IS NULL;

CREATE TABLE us_dead_letters (
  sequence     INTEGER NOT NULL PRIMARY KEY,
  entity       TEXT NOT NULL,
  key_hash     BLOB NOT NULL,
  key_json     TEXT NOT NULL,
  kind         TEXT NOT NULL,
  payload_json TEXT,
  failure_json TEXT NOT NULL,        -- round-trips through SyncFailure.fromJson

);
CREATE INDEX us_dead_letters_age ON us_dead_letters(failed_at);
```

Installation:

- Idempotent `CREATE TABLE IF NOT EXISTS` + index creation, all DDL **and** the version bump in one
  transaction, tracked in `us_meta.schema_version`.
- Refuse to open when `us_meta.schema_version > packageSchemaVersion` with a typed `SyncSchemaTooNew`
  (no silent downgrade, no data corruption).
- At `open()`: reclaim expired leases (`inflight AND lease_until < now → pending`), run maintenance,
  validate every generated adapter against `PRAGMA table_info` and against transport capabilities.
- Warn at `open()` when a synced table participates in `ON DELETE CASCADE`
  (`PRAGMA foreign_key_list`): cascade deletes bypass the facade and therefore never reach the
  outbox.
- Recommend and report PRAGMAs in `diagnostics()`: `journal_mode=WAL`, `synchronous=NORMAL|FULL`,
  `busy_timeout` (multi-isolate safety). Durability of the outbox inherits the app's PRAGMAs.
- `syncSchemaSql` constant exported for teams that run migrations themselves.

`AUTOINCREMENT` gives total causal ordering without a UUID dependency. `key_hash` keeps index size
small and prevents JSON canonicalization bugs from corrupting uniqueness; `key_json` remains for the
wire.

### Outbox state rules

1. **Delivery-certainty immutability (v3).** A row with `delivered_maybe = 1` is never mutated.
   Coalescing applies only to `state='pending' AND delivered_maybe=0` rows. `delivered_maybe` is set
   to 1 at claim (conservative) and reset to 0 only when the adapter proves `notSent`. This replaces
   v2's attempt-count rule, so an offline launch no longer freezes every write.
2. **Per-key head-of-line ordering.** A row is claimable only when no older pending/inflight row
   exists for the same `(entity, key_hash)`. Guarantees causal order per record across retries and
   makes out-of-order application impossible at the adapter.
3. **Supersede on ack.** After an `upsert`/`delete` ack, older pending rows for the same key are
   obsolete (the newer row fully determines final state) and are deleted in the same transaction.
   An `update` (delta) ack never supersedes anything. This bounds queue growth.
4. **No `parked` state.** Permanent failures move to `us_dead_letters` in the same transaction that
   deletes the outbox row. One source of truth; `retryParked()` re-inserts into the outbox.
5. **`notSent` release.** On `TransientFailure(notSent)`, in the ack transaction:
   - set `state='pending'`, `delivered_maybe=0`, schedule `next_attempt_at`;
   - if **no** other pending row exists for the key, keep the row as the coalescing target;
   - if another pending row **does** exist (it was created while this row was in flight), that newer
     row defines the intended final state: delete the released row, and if the newer row is an
     `update`, promote it to a full `upsert` from the current local row. This keeps exactly one
     coalescible row per key and preserves the unique partial index.
6. **Promotion.** When a row is parked or superseded by an earlier failure, a newer pending `update`
   for the same key has no base to apply to. With `promoteDependentUpdates` (default `true`), read
   the current local row and rewrite the change as a full `upsert` (`ChangePromoted`). If the local
   row no longer exists, park the dependent row instead of sending a delta against nothing.
7. **Create+delete is a delete, not a cancellation (v3).** `DELETE` is idempotent; "this key never
   existed remotely" is not knowable on a device. Coalescing `upsert → delete` therefore yields one
   `delete` row, which converges even if another device created the key while we were offline.
   `cancelUnsyncedCreateThenDelete: true` restores v2 behaviour (delete both plus the tombstone) for
   append-only entities whose keys are provably local-origin; with cancellation the tombstone is
   cleared, which means a real remote row with that key *will* be pulled back later.

### Coalescing rules (evaluated inside the enqueue transaction)

| Existing (pending, `delivered_maybe = 0`) | New operation | Result |
|---|---|---|
| upsert | update | merge delta into the upsert after-image |
| upsert | delete | **replace with delete** (default); cancel both + clear tombstone only if `cancelUnsyncedCreateThenDelete` |
| update | update | merge deltas |
| update | delete | replace with delete |
| delete | upsert | replace with upsert; clear the local tombstone |
| update | (no local row) | API-level no-op; `patch` returns `null` |
| any | any while a `delivered_maybe=1` row exists | new pending row (immutability rule) |

Acknowledgment deletes only the row whose sequence was acked; per-key ordering means no newer row can
already be in flight.

## 8. Guarantees and the failure modes they prevent

| Failure mode | Guarantee |
|---|---|
| Hand-typed table/column strings | typed table info, companions, generated entity refs |
| `INSERT OR REPLACE` semantics (lost columns, cascades) | typed `insertOnConflictUpdate` / `update().write()` |
| Retention purge skipped when the queue is idle | maintenance runs independently of drain outcome |
| Truncated pages plus a clock-derived watermark | cursor + `hasMore` loop |
| Rows sharing the watermark timestamp are skipped | keyset cursor with key tiebreaker |
| A process-wide boolean drain lock | atomic claim + expiring lease, recovered at `open()` |
| Dropping a permanently failing change | `us_dead_letters` + explicit retry/discard |
| Row payloads leaking into logs | no payloads in events/errors unless opted in |
| Auth detected by sniffing error strings | sealed `SyncFailure` + capability negotiation |
| One queued operation per write | coalesced outbox + per-key ordering |
| A stale retry overwriting a newer write | delivery-certainty immutability + head-of-line ordering |
| Airplane-mode edits replayed as N requests | `notSent` release keeps rows coalescible |
| Create-then-delete resurrecting a remote row | coalesce to an idempotent `delete` |
| Remote deletes resurrecting locally | tombstones suppress while they exist (not only while unacked) |
| Offline edits losing `newestWins` | engine stamps `updated_at` when omitted |
| Retry knobs that are never read | `Backoff` sealed policy, always applied, with jitter |
| Deletes not propagating | tombstones in both directions, cursor-gated retention |
| A user switch leaking the previous user's rows | `purge(localData: true)` + `purgeOnUserChange` |
| Network I/O inside a local write | outbox is synchronous and local; drain is the only network path |
| Silent overwrite of existing local data on adoption | `SyncBootstrap` policies, run exactly once |
| Invisible coalescing | `SyncReport.coalesced/cancelled` + events |

Delivery semantics to document: **at-least-once push**, idempotent by construction (`upsert` /
`update` / `delete` are naturally idempotent; `idempotencyKey` protects server-side dedupe),
**eventually consistent pull** (cursor per entity), **per-key causal ordering**, **no silent data
loss** (permanent failures are parked, remote losers of conflicts are persisted, never dropped).

### Offline sequence walk-through (regression fixture)

`create(t1,v1) → patch(t1,v2) → create(t2,w1) → patch(t2,w2) → remove(t1)`, all offline:

| Case | Outbox when reconnecting | Pushes |
|---|---|---|
| No claim yet, or every failure was `notSent` | `delete t1`, `upsert t2(w2)` | 2 |
| At least one `maybeApplied` claim per key | `upsert t1(v1)`, `upsert t2(w1)`, `delete t1`, `update t2(w2)` | 4, t1 transiently exists |
| `t1` create parked, `t2` fine | `delete t1` (idempotent no-op), `upsert t2(w2)` | 2; a trailing `t2` update would be promoted |
| `cancelUnsyncedCreateThenDelete: true`, no claims | `upsert t2(w2)` + cleared tombstone | 1, but a pre-existing remote `t1` resurrects |

End state in the first three rows: server and local both contain `t2(w2)` and no `t1`.

## 9. Integrating an existing Drift project

1. **Native (recommended).** Change the write calls you want synced:
   `into(tasks).insert(c)` → `sync.tasks.create(c)`. Reads, joins, `watch`, transactions and DAOs
   stay exactly as they are.
2. **Queue-only (gradual migration).** Keep the existing DAO and call
   `sync.tasks.markDirty(id, kind: SyncChangeKind.update)` after writing. No atomicity between the
   local write and the outbox entry — documented, and the reason it is not the default.
3. **Reconcile mode (phase 6, opt-in).** Uses drift's typed `db.tableUpdates()` stream
   (`TableUpdate { table, kind }`), **not** `QueryInterceptor` SQL parsing. Rebuilds insert/update
   changes by re-scanning rows by `updatedAt`. Limitation, stated up front: it cannot recover
   **deletes** (the update log carries no keys), so deletes must go through the facade.

Our schema does not appear in the consumer's `@DriftDatabase`, so there are no generated-code
conflicts and no `schemaVersion` bump. At `open()` we validate every generated adapter against
`PRAGMA table_info` and transport capabilities, failing fast with a typed error naming the entity,
column and expected kind.

**Bootstrap is part of adoption** (§5.8): choose `MergeByUpdatedAt` for existing apps, `UploadLocal`
for local-first apps with authoritative device data, `ServerWins` for server-authoritative apps.

**Ordering boundary (v3).** Only per-key ordering is promised. Two different keys, two different
entities, or two different tables may be delivered out of causal order. If `t2` has a foreign key
into `t1`, a `t1` delete can reach the server before a `t2` upsert that references it. Recommended
patterns: keep dependent rows in the same entity, use soft references, or rely on server-side
deferred constraints. `unitOfWork` guarantees **local** atomicity only.

- **Sealed classes + exhaustive `switch`** for changes, outcomes, failures, certainty, cursors,

  is contained. Nested-transaction/savepoint behaviour is verified in P3 tests (the API promises
  that `sync.tasks.*` composes inside a caller transaction).

## 11. Testing and quality gates

**Shipped test doubles (`lib/testing.dart`, no `drift/native` dependency)**

- `FakeTransport`: in-memory server with programmable failures, latency, delivery certainty,
  authoritative timestamps, tombstones, duplicate/out-of-order delivery, and real pagination.
- `SyncTestHarness`: in-memory drift database + schema install + fake server; accepts a
  `QueryExecutor` so consumers can supply native, web, or encrypted executors.
  `await h.settle()` drains and pulls until idle with a deadline; `h.server.failNext(...)`,
  `h.server.rows('tasks')`.
- `runTransportContractSuite(factory)`: conformance suite adapter authors run in their own packages.
  Covers ack completeness, idempotency, tombstone handling, cursor semantics, failure
  classification, delivery-certainty honesty (including the negative case), payload format,
  `maxBatchBytes`, idempotent deletes, and full-row pages.

**Engine invariants tested against real SQLite (`drift/native`)**

1. Local write + outbox append atomic; rollback leaves neither.
2. Re-push after a simulated crash is idempotent.
3. `delivered_maybe=1` rows are immutable; coalescing never rewrites them.
4. `notSent` release keeps a row coalescible, and with an existing newer pending row it deletes the
   released row and promotes the newer `update` to a full `upsert`.
5. Per-key head-of-line ordering: no newer change is pushed before an older one resolves.
6. Pull pagination never skips a row (including equal `updated_at` values).
7. Remote delete does not resurrect locally; local delete does not resurrect remotely; remote
   tombstones are recorded for absent rows.
8. A tombstone keeps suppressing pulls **after** `acked_at` is set, until cursor-gated purge.
9. Coalescing laws for every existing/new operation pair, including `create+update+delete → delete`
   and the opt-in cancellation variant.
10. Lease expiry reclaims in-flight rows; `open()` recovers immediately.
11. Permanent failure parks the change; the rest of the batch still syncs; dead letters round-trip
    through JSON; a trailing `update` is promoted (or parked with it) when its base is gone.
12. Queue size and outbox bytes stay bounded over many write/drain cycles while online
    (`OutboxPressure` emitted, nothing auto-dropped).
13. Session switch purges outbox, cursors, tombstones, conflicts, dead letters and optionally local
    rows.
14. Conflicts are persisted, resolvable, and never consume the remote row on manual policy.
15. Bootstrap runs exactly once, is resumable, and produces the same end state when interrupted.
16. Capability mismatches fail `open()` with an actionable typed error.
17. Schema downgrade is refused; schema install is transactional and idempotent.
18. `sync.tasks.*` composes inside a caller transaction (savepoints) and rolls back together.
19. Offline `create/update/delete` sequences produce the exact outbox shapes and push counts in the
    §8 fixture table.
20. `SyncReport.coalesced/cancelled` match the writes performed in every fixture.

**Builder tests**: `build_test` goldens and diagnostics (missing/inferred key, non-DateTime
`updatedAt`, unsupported column type, name collision without prefix, missing `@SyncDatabase`,
generated-signature drift).

**CI**: `dart format --output=none --set-exit-if-changed .`, `dart analyze --fatal-infos`,
`dart test`, `pana`, `dart pub publish --dry-run`; Dart stable + beta matrix.

No "structural" security tests that assert the absence of features; every claim maps to an invariant.

### Also assumed unless corrected

- Runtime dependency list is exactly `drift` (+ `meta` if needed). No `uuid` (autoincrement sequence +
  install id), no `collection`, no `clock` (injected `SyncClock`).
- Builder member depends on `build`, `source_gen`, `analyzer`, `build_test`.
- `autoDrain` defaults to `false`; apps call `syncNow()` at launch / on connectivity / on resume.
- Tombstone retention defaults to 30 days, purged only when every entity cursor is past the

- `stampUpdatedAt` defaults to `true` when the entity declares `updatedAt`.
- `dispose()` never closes the consumer's database.
- No adapter, auth, crypto, HTTP, realtime, or scheduling code in this package — ever.
